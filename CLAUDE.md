# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Lifely is a Flutter app for university students that combines task planning with mood tracking. It uses Firebase Auth and Cloud Firestore as the backend (project `lifely-dfe39`), with Android and web as the configured Firebase platforms (`lib/firebase_options.dart` is generated by FlutterFire, so don't hand-edit it).

## Commands

```bash
flutter pub get                          # install dependencies
flutter run                              # run on a connected device/emulator
flutter analyze                          # lint (flutter_lints, see analysis_options.yaml)
flutter test                             # run all tests
flutter test test/ai/quick_add_parser_test.dart   # run a single test file
flutter test --plain-name "tonight defaults"       # run a single test by name
flutter build apk --release              # release build (R8 uses android/app/proguard-rules.pro)
firebase deploy --only firestore         # deploy firestore.rules + firestore.indexes.json
```

The tests are pure-Dart unit tests of the logic (`lib/ai/`, `lib/services/reminder_engine.dart`, `lib/utils/`, models). `AppStore` and `LifelyApp` touch `FirebaseService.instance` (and so `FirebaseAuth.instance`), so a widget test that pumps them needs Firebase mocked or initialized. Keep logic that should be tested out of the store and pass `now` in explicitly, as the parser, scheduler and reminder engine do.

## Architecture

**State: one `ChangeNotifier` store, no state-management package.** `AppStore` (`lib/data/app_store.dart`) holds all app state: profile, tasks, moods, planner blocks, notifications, and theme mode. `AppScope` (an `InheritedNotifier`) exposes it, and screens read it with `AppScope.of(context)` (`AppScope.read(context)` in callbacks such as timers, where you don't want a rebuild dependency). `LifelyApp` creates the store, wraps `MaterialApp` in an `AnimatedBuilder` on it, and picks between `AuthFlow` (splash → login/signup) and `LifelyShell` based on `store.isAuthenticated`.

**Persistence is optimistic, with a local cache.** Each `AppStore` mutation does three things in order: it updates the in-memory list, writes the whole list as JSON to `SharedPreferences` (`lifely_*_cache` keys), and calls `notifyListeners()`. Only then does it call the matching `FirebaseService` method through `_sync(label, op)`, which records `syncError`/`lastSyncedAt` (shown on the Dashboard and in Settings) rather than throwing. On startup the cache is shown first, then `refresh()` reloads each collection from Firestore; a collection that fails keeps its cached copy. The cache is tagged with its owner's uid (`lifely_cache_owner`) and cleared on logout, so never load it without that check. To add a new entity, follow this same pattern and add `toJson`/`fromJson`/`copyWith` to `lib/models/app_models.dart`. `fromJson` must keep reading documents saved in older shapes (for example, `PlannerBlock` falls back to its old `timeLabel` field).

**Firestore layout** (`lib/services/firebase_service.dart`, a singleton): `users/{uid}` holds the profile, and per-user subcollections `tasks`, `moods`, `planner`, and `notifications` hold one document per item, keyed by the model's `id`. The service also has `watch*()` streams, but the store currently uses one-shot `get*()` reads. `firestore.rules` allows each signed-in user to read and write only `users/{their uid}/**`.

**"AI" is on-device heuristics, not an LLM.** `lib/ai/ai_planning_engine.dart` contains `AiTaskPrioritizer` (keyword- and deadline-based scoring, most urgent first), `AiMoodAdvisor`, and `AiScheduler`, which proposes time blocks for one day around existing planner blocks and caps the day by the latest mood (a check-in older than 24h counts as Steady). `lib/ai/ai_quick_add.dart` parses due dates, times, durations and categories out of free text ("essay tomorrow 3pm for 1h") and powers the Add screen's rewrite. `lib/ai/ai_notes_summarizer.dart` does keyword/stop-word extraction for key points, action items, and deadlines. Scoring weights and the color palette live in `lib/utils/constants.dart` (`AiScoring`, `AppColors`). OCR uses Google ML Kit text recognition through `OcrService` (`lib/utils/ocr_service.dart`) together with `image_picker`. Its output feeds the Add screen and the summarizer. The ProGuard rules exist to keep ML Kit classes in release builds.

**Reminders are in-app only** (no push notifications). `ReminderEngine` (`lib/services/reminder_engine.dart`) produces overdue, due-soon, daily-digest and mood check-in alerts with deterministic ids. `AppStore.generateReminders()` runs it after load, after task changes, on app resume and every 5 minutes from `LifelyShell`. Dismissed reminder ids are remembered in preferences so they don't come back, and quiet mode (`setQuietFor`) pauses generation.

**Dates:** a task's `scheduledAt` is its due date and time. Planner blocks have a `start` and `durationMinutes`, plus an optional `taskId` when the AI scheduler created them. Use the helpers in `lib/utils/time.dart` (`isSameDay`, `addDays`, `daysBetween`, `formatDueLabel`, `consecutiveDayStreak`, …). They are DST-safe, unlike `Duration` arithmetic or `.difference(...).inDays` on local dates.

**Navigation:** `LifelyShell` is a bottom-nav `Scaffold` with five tabs (Home/Dashboard, Planner, Add, Journal, Alerts). Each tab screen receives `themeMode`/`onThemeModeChanged` callbacks. All secondary screens are pushed through helper functions in `lib/utils/navigation.dart` (`openTaskDetails`, `openInsights`, etc.), which share a fade-and-slide `PageRouteBuilder`. Add new pushed screens there instead of calling `Navigator.push` directly.

**UI building blocks:** reusable widgets live in `lib/widgets/` and are grouped by kind (`cards/`, `tiles/`, `buttons/`, `banners/`, `charts/` using `fl_chart`, etc.). Screens use `LifelySliverAppBar` for headers. Snackbars are deliberately kept to Undo after destructive actions; other feedback is shown inline. Empty lists use `EmptyState` and errors use `ErrorBanner` (`lib/widgets/ui_state/error_banners.dart`). `DateTimeField`, `showPlannerBlockSheet` and `showRescheduleSheet` are the shared date and block inputs. The theme comes from `buildTheme(Brightness)` in `lib/theme/app_theme.dart` (Google Fonts).
